# Performance and lightweight design

KS - TV Launcher must stay a lightweight, high-performance launcher. Responsiveness comes before decoration, but never at the cost of core Android TV behaviour.

## Requirements
- **Startup**: keep cold start short. No work in `Application.onCreate`; create dependencies lazily.
  - **Home ready is reported**: `ReportDrawnWhen { appsLoaded }` in `MainActivity` calls `reportFullyDrawn()` once the app grid has its apps, so `am start -W`, Macrobenchmark (`timeToFullDisplay`) and the baseline profile measure "Home ready", not only the first frame.
  - **Baseline profile**: a start-up and Home profile is shipped in the APK (`tv/google-tv/src/release/generated/baselineProfiles/`), generated by the test-only `:tv:google-tv-baselineprofile` module on a TV emulator (`./gradlew :tv:google-tv:generateReleaseBaselineProfile`) and installed on the TV by `profileinstaller`, so the first starts after an install or update run compiled code. Regenerate it when Home or start-up code changes noticeably. `StartupBenchmark` in the same module measures cold start with and without it.
  - **Targets** (owner's 55 inch TV, release build; [per-platform plan](plan-per-platform.md)): first frame at most 450 ms, Home ready at most 700 ms.
  - Only English and Hindi are kept from libraries' resources (`androidResources.localeFilters`).
  - **Instant Home**: the last app list is kept in `files/app_list.json` (`AppListCache`, `AppListCodec`) and shown at once on a cold start; the fresh `LauncherApps` scan replaces it, and a changed list is written back. Home's other sources (clock, settings, profile, device, pins, weather) arrive at about the same time as the first frame, so what remains between the first frame and Home ready is composing and drawing Home.
  - **Daily work after start**: about 5 s after Home is first shown (once per process, off the main thread), KS re-registers the daily reminder and update-check work whose switches are on, as unique work with the KEEP policy, so an existing schedule is left alone. This starts WorkManager on every cold start, after Home is up. A force-stop makes Android drop an app's scheduled jobs, and without this they stayed gone until the next TV restart or setting change ([reminders](reminders.md), [app-updates](app-updates.md)). Leftover update files are tidied in the same step.
- **Background**: no persistent service, no manifest (startup) receivers, no wake locks. Weather refreshes periodically and is configurable ([weather](weather.md)); reminders use scheduled work ([reminders](reminders.md)).
  - **WorkManager's own manifest entries are accepted.** The library merges in its own permissions (`WAKE_LOCK`, `RECEIVE_BOOT_COMPLETED`, `FOREGROUND_SERVICE`, `ACCESS_NETWORK_STATE`), services and receivers so it can run scheduled work. That is the library, not KS: KS code never acquires a wake lock, never starts or declares a service, and declares no receiver of its own in the manifest. The same holds for `profileinstaller`'s `ProfileInstallReceiver` (it only answers the system and adb, guarded by the `DUMP` permission).
- **No polling** for clock, app or system status. Use system broadcasts, observers and callbacks, registered only while the screen is visible.
- **Compose**: lazy rows and grids; avoid needless recomposition; animate in the draw or layer phase; keep UI state immutable.
- **Images**: load asynchronously, cache icons and artwork, and do not load large wallpapers until they are needed. Release what is no longer used.
- **Effects**: light animations; blur only where [design-system](design-system.md) allows.
- **Network**: no unnecessary requests; cache the last result.
- **Coroutines and Flow**: stop upstream work when nothing collects; avoid leaks and needless allocations.
- **D-pad**: focus feedback is immediate.

## User switches ([settings](settings.md))
- Dynamic wallpaper on/off.
- Reduce motion (no animations).
- Transition speed (shorter animations mean fewer frames on a slow TV; default 0.5×).
- Glass intensity; Low means no blur.

## Checks
- Test on real Google TV hardware.
- Watch memory, CPU and startup time during the Stage 5 performance pass.

## How Stage 1 meets this
- `KsApplication.onCreate` does nothing; `AppContainer` is lazy; one DataStore file.
- Clock: `ACTION_TIME_TICK` broadcast through `minuteTicker`, registered at runtime, removed 5 s after Home stops.
- TV name: a content observer, not a timer.
- `animateDpadFocus`: one animation, read only in layer and draw lambdas, so frames redraw without recomposing.
- With motion off, animation specs snap, so no animation frames run.
- Blur: only the weather pill and dialogs; nothing is registered with Haze when blur is off or below API 31.
- Only the libraries Stage 1 uses are in the build. Coil and Palette arrive in Stage 2, WorkManager in Stage 5.
